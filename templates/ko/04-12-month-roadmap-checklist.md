# 12개월 로드맵 — 인쇄용 체크리스트

『나는 AI를 사장으로 고용했다』 부록 E, 템플릿 ④(16장용).

**시작 예정일: ____________**   → 1개월 차 종료 ____________, 12개월 차 종료 ____________

순서가 속도보다 중요합니다. 위험이 낮고 되돌리기 쉬운 일부터, 되돌리기 어려운 일은 일부러
맨 나중에 배치했습니다. 회사 헌법을 잘못 쓰면 다시 쓰면 됩니다. 실계좌에 돈을 잘못 넣으면
되돌릴 수 없습니다.

---

## 1개월 차 — 첫 직원 채용 · 3~5장

- [ ] 클로드를 내 컴퓨터에 설치하고 실행되는 것을 확인
- [ ] 회사 헌법 작성(`CLAUDE.md`) — 이 팩의 템플릿 ①
- [ ] 텔레그램 봇 생성, 토큰과 chat_id 확보
- [ ] 아침 브리핑 봇 실행 — 이 팩의 템플릿 ②
- [ ] 작업 스케줄러에 등록하고, 다음 날 아침 스스로 실행된 것을 확인

**이 시점에 있는 것:** 한 장짜리 회사 헌법, 매일 정해진 시각에 오는 메시지 하나, 그리고
직원에게 일을 넘긴다는 첫 감각.
**아직 없는 것:** 외부에 보여줄 결과물, 수익.

## 2개월 차 — 중간 점검 · 6장

- [ ] 6장 체크리스트를 짚으며, 1개월 차에 만든 것이 실제로 잘 도는지 하나씩 확인
- [ ] 막힌 것을 목록으로 적고 뚫었다(또는 미루는 이유를 적었다)

새로 만드는 달이 아니라 만든 것을 단단하게 만드는 달입니다. 뭔가 새로 얹고 싶은 충동을
누르세요 — 지금 목표는 이미 있는 것을 견고하게 하는 것입니다.

## 3개월 차 — 쇼츠 채널 하나를 끝까지 · 7~8장

- [ ] 채널 콘셉트 결정, 시작하기 전에 "접는 조건(kill condition)"을 먼저 적어 둠
- [ ] 브랜드 계정 채널 생성
- [ ] 구글 인증 플랫폼 설정(브랜딩 · 대상 · 데이터 액세스)하고 OAuth 키 발급
- [ ] 쿼터를 구글 공식 페이지에서 **오늘 기준으로** 확인 — 숫자는 바뀝니다
- [ ] 내가 아무것도 누르지 않아도 파이프라인이 업로드
- [ ] 토큰 만료 알람 설치(약 7일마다 스스로 죽습니다)

**이 시점에 있는 것:** 스스로 기획하고 만들고 올리는 채널 하나, 매일 쌓이는 조회수 데이터.
**아직 없는 것:** 큰 조회수, 수익화 자격(광고 수익은 **한 채널 기준** 구독자 1,000명부터 —
여러 채널 합계는 어느 자격에도 보태지지 않습니다).

## 4~5개월 차 — 안정화 · 8장

- [ ] 성과 데이터로 스스로 고치는 루프를 한 달 내내 지켜봄
- [ ] 루프가 기록한 라벨이 파이프라인이 실제로 쓴 값과 일치하는지 확인(쓰려던 값이 아니라)
- [ ] 그다음에야: 두 번째 채널을 검토

## 6개월 차 — 블로그 + SNS 얼굴 하나 · 9장

- [ ] 블로그 자동 발행
- [ ] SNS 페르소나 개설, 자기 목소리로 글을 올림

## 7~8개월 차 — 쌓이게 두기 · 9장

- [ ] 글 편수가 광고 네트워크 신청 조건을 충족
- [ ] SNS 계정의 첫 실제 반응을 읽고 조정

**이 시점에 있는 것:** 검색엔진에 남는 자산 하나, 사람처럼 말하는 계정 하나.
**아직 없는 것:** 광고 수익 — 아직 신청 조건을 채우는 단계입니다.

## 9개월 차 — 증권사 API + 모의투자만 · 10~11장

- [ ] 증권사 API 신청하고 키 발급
- [ ] **모의투자로 최소 1개월.** 절대 실전부터 시작하지 않기.
- [ ] 모의투자 실행이 실계좌 기록 근처에도 쓰지 않는지 확인(실잔고·시트·알림 무접촉)

**이 시점에 있는 것:** 신청해 본 경험, 모의투자 한 달 치 기록.
**아직 없는 것:** 실전 성과. 모의투자는 실전과 다른 지표입니다.

## 10~11개월 차 — 믿기 전에 검증 · 12장

- [ ] 전략을 만든 구간이 아니라 **홀드아웃** 구간에서 백테스트 실행
- [ ] 샤프비율 **와** 낙폭이 둘 다 개선 — 하나를 다른 하나의 희생으로 얻지 않기
- [ ] 유니버스를 사후에 골랐다면 생존편향을 소리 내어 명시
- [ ] 통과한 경우에만: 잃어도 되는 아주 작은 금액으로 실전 전환

여기서의 기각은 실패가 아니라 결과입니다. 그렇게 기록하세요.

## 12개월 차 — 관제실 · 13~14장

- [ ] 미니 트윈 실행 — 이 팩의 템플릿 ③
- [ ] 회사 전체를 하나의 일일 보고로 묶음
- [ ] 보고가 내가 묻기 전에 먼저 도착

**이 시점에 있는 것:** 관제실 하나, 스스로 보고하는 회사, 그리고 정말로 회사를 1년 굴려 본
사람이라는 자기 자신.

## 막혔을 때 대처하는 3원칙

이 부분은 눈에 잘 띄는 곳에 붙여 두세요.

1. **추측으로 고치지 말고, 먼저 지금 상태를 읽으세요.** 무엇이 잘못됐는지 모르는 채로 이것저것
   바꾸면 원인이 더 흐려집니다. 로그를, 화면을, 에러 메시지를 있는 그대로 먼저 보세요.
2. **고칠 땐 조금씩, 되돌릴 수 있게 고치세요.** 한 번에 여러 곳을 바꾸면 무엇 때문에 나아졌고
   무엇 때문에 나빠졌는지 알 수 없게 됩니다.
3. **막히면 클로드에게 화면 그대로, 에러 메시지 전체를 보여주세요.** 요약하지 말고 원문 그대로
   복사해서 붙여넣으세요. "대충 이런 느낌의 오류"라고 설명하는 것보다, 원문 그 자체가 항상 더
   정확합니다.
